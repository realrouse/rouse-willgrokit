# X / Twitter content ideas for `@LBRYFoundation`

## Goal

Keep a **trustworthy public heartbeat** so that anyone — human or machine — who checks the official account does **not** conclude that LBRY is abandoned.

Secondary goals:

- Route serious people into **Discord**, **forum**, and **docs**  
- Teach the **protocol vs app vs company** distinctions  
- Amplify **only** durable artifacts  

Non-goals:

- Viral growth at any cost  
- Daily posting quotas that force fluff  
- LBC market content  

## Cadence (intentionally modest)

| Trigger | Action |
|---------|--------|
| **Minimum** | ~**1 post per month** even in a quiet month (education or signpost) |
| **Forum announcement / release** | Same-day X link (minimal rewrite) |
| **Meaningful GitHub tag** | Link tag + forum notes |
| **Nothing shipped** | Educational post or FAQ correction — **not** a fake “monthly update” |

Quality over frequency. Dead air for a year is worse than six dull posts a year.

## Content pillars

### Pillar A — Signposts (highest safety)

Point at things that already exist.

| Idea | Example angle |
|------|----------------|
| Discord is HQ | “Day-to-day development and discussion: chat.lbry.org” |
| Forum first | “Release notes and announcements land first on forum.lbry.org” |
| Stack map | Link https://lbry.org/downloads (Nova, daemon, CLI, hub, chain) |
| Board / nonprofit | Link https://lbry.org/board and mission |
| Projects catalog | Link https://lbry.org/projects |
| GitHub org | “Component work is public here…” |

### Pillar B — Protocol education (infinite, non-hype)

One concept per post. Evergreen.

| Topic seeds | Notes |
|-------------|--------|
| Claim / channel / stream | Definitions only |
| What the **daemon** does | Brain of the client stack |
| What a **hub** is for | Search / SPV-style roles — keep accurate |
| Protocol vs **app** vs **website** | Critical myth-bust |
| `lbry://` resources | How addressing works at a high level |
| Publishing & supporting claims | LBC **utility** language only |
| Seeding / hosting blobs | Operator public-good framing |
| Why multiple clients can exist | Odysee, Nova, CLI, community clients |

### Pillar C — Operator & builder utility

| Idea | Notes |
|------|--------|
| How to report issues | GitHub vs forum vs Discord |
| Where developers talk | Discord + forum Developers category |
| Awesome / community tools | Only tools that exist today |
| “How to verify the network is alive” | Checklist post → docs later |

### Pillar D — Honest status & myth-busting

| Idea | Notes |
|------|--------|
| Quiet periods are OK | Explicitly reject invented hype |
| Inc / Foundation / protocol / Odysee | Glossary thread (or link a site page) |
| “No public roadmap on site; track GitHub” | Already site policy — can restate |
| Correct “LBRY is fully dead” | Without overselling unreleased clients |

### Pillar E — Ship-level product posts only

Gate:

> A usable artifact exists (binary, tag, or explicit source-only alpha with build instructions) **and** a forum post describes it.

Until then: point to **where work is tracked**, not to imagined launch days.

## Sample posts (draft menu)

These are **drafts for human edit/approval**. Prefer linking over adjectives.

### A. Discord as headquarters

> Most day-to-day LBRY development discussion, support, and community coordination happens in the LBRY Foundation Discord:  
> https://chat.lbry.org  
>  
> Long-form announcements and release notes: https://forum.lbry.org

### B. Forum-first releases

> Software announcements and release notes are published first on the LBRY Forum.  
> https://forum.lbry.org  
>  
> This account will link there when there is something concrete to point to.

### C. Stack map

> LBRY is a stack, not a single app: clients (e.g. Nova), daemon, CLI, hub, and blockchain.  
> Entry points: https://lbry.org/downloads

### D. Protocol vs interface

> LBRY is a content protocol and network. Applications and websites are interfaces to that network.  
> If one interface is unavailable, published claims and other clients can still exist independently of it.

### E. Nonprofit clarity

> The LBRY Foundation is a non-profit organization dedicated to the growth, development, and adoption of the LBRY network in a community-driven way.  
> Mission and board: https://lbry.org · https://lbry.org/board

### F. Community projects

> Community-built tools on and for the LBRY protocol are catalogued here:  
> https://lbry.org/projects

### G. Utility LBC only (use sparingly)

> On LBRY, credits are used for network operations such as publishing and supporting claims.  
> This account does not discuss markets or price.

### H. Quiet-period honesty (trust builder)

> We post when there is durable information: docs, releases, governance, and protocol education.  
> Silence means we are not inventing updates.  
> For living technical work, use Discord and the forum. For code, use GitHub.

### I. Contribution doors

> Prefer discussion and testing notes on the forum; real-time chat in Discord; development tracking on GitHub.  
> https://forum.lbry.org · https://chat.lbry.org · https://github.com/LBRYFoundation

### J. After a real forum release (template)

> [Component] [version/tag] notes are on the forum:  
> [forum URL]  
>  
> Source / downloads: [link]

## 30-day starter calendar (quiet month)

Use only if nothing major ships. All pillars above; zero vapor.

| Week | Pillar | Post |
|------|--------|------|
| 1 | Signpost | Discord is HQ + forum for releases |
| 2 | Education | Protocol vs app vs website |
| 3 | Signpost | Downloads / stack map |
| 4 | Education or myth-bust | One glossary item (claim, daemon, or hub) |

If a real release lands, **replace** a calendar slot — don’t invent a fifth post for volume.

## Approval flow (lightweight)

```text
Idea / Discord lore
    ↓
Is there a public artifact?  ──no──→ Write forum/docs first (or don’t post)
    ↓ yes
Draft in plain language (human)
    ↓
Check: nonprofit voice? no markets? no promises?
    ↓
Optional: grammar pass (human or tool)
    ↓
Post on X + (if useful) Reddit/Telegram pointer
```

### Suggested RACI (adapt to board reality)

| Step | Responsible |
|------|-------------|
| Draft | Any trusted contributor |
| Accuracy | Person closest to the fact (e.g. CTO for software claims) |
| Voice / policy | President or designated comms approver |
| Publish | Whoever holds account access |

Keep the queue small. A shared doc or Discord `#public-comms` (staff-only) is enough.

## What not to post (checklist)

- [ ] Unshipped software presented as available  
- [ ] Dates for future miracles  
- [ ] LBC price, exchanges, “buy,” “hold,” moon energy  
- [ ] Vague “big things coming”  
- [ ] Engagement bait unrelated to mission  
- [ ] Political campaign content  
- [ ] Ambiguous commercial advertising tone  
- [ ] Screenshots of private Discord drama

## Metrics that match the mission

Prefer metrics that reward **legibility**, not clout:

| Better | Worse |
|--------|--------|
| Referral clicks to forum / Discord / docs | Raw impressions alone |
| New GitHub stars/forks on real components | Follower vanity without context |
| Forum topics that stay useful | Quote-tweet wars |
| Support questions answered with durable links | Ratio engagement |

A “successful” month can be **one** post that prevents a hundred “is LBRY dead?” misunderstandings.
