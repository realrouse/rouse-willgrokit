# Growth ideas: make LBRY legible again

## What “growth” means here

For a **nonprofit protocol foundation**, growth is not primarily “more engagement on X.”

Growth means more people who can:

1. **Understand** what LBRY is (protocol, network, clients)  
2. **Find** the living community (especially Discord)  
3. **Use or run** something real (client, daemon, hub, tools)  
4. **Contribute** (code, docs, ops, guides, moderation, grants)  
5. **Trust** that official silence ≠ death — and official speech ≠ hype  

If those five improve, social metrics follow. If social metrics rise without those five, trust burns.

---

## Strategy in one line

> **Settle truth on durable surfaces. Keep Discord as HQ. Use public social as a window and a door.**

---

## Layer 1 — Legibility (foundation for everything)

Without this, every other growth idea fails.

| Work item | Why it matters | Surfaces |
|-----------|----------------|----------|
| **Glossary**: Inc vs Foundation vs protocol vs Odysee vs Nova vs daemon | Ends the #1 confusion | lbry.org page → X series |
| **Stack map** on downloads page | Answers “what do I install?” | lbry.org/downloads |
| **“Where things happen”** page | Discord / forum / GitHub roles | lbry.org/contact or new page |
| **Pinned X post** | Instant orientation | X |
| **Forum release category discipline** | Creates citeable ship log | forum.lbry.org |
| **Honest empty states** | “No binaries yet” is better than silence + rumor | downloads pages |

**Definition of done:** a smart stranger can answer “what is LBRY *now*?” in five minutes without joining Discord.

---

## Layer 2 — Doors into Discord (without emptying Discord)

Discord is already the center of gravity. Growth should **widen the doorway**, not force all culture onto X.

| Idea | Detail |
|------|--------|
| **Standard invite block** | Same short text on site, X, forum sidebar, Reddit sidebar |
| **Role of Discord in onboarding** | “Come for answers; stay for development” |
| **Public topic → Discord deep-dive** | X/forum states the durable fact; “discussion continues in Discord” |
| **Office hours (rare)** | Announced on forum + X; held in Discord; notes back to forum |
| **Contributor map** | Which channels for support vs dev vs random |

Avoid: mirroring every Discord message to X. That creates noise and policy risk.

---

## Layer 3 — Builder growth

Builders care about **code, APIs, and whether the network is real**.

| Idea | Notes |
|------|--------|
| **Tagged releases with notes** | Even small tags beat invisible commits |
| **“Build from source” paths** | Especially while binaries are sparse |
| **Protocol tutorials** | Already valuable; promote without hype |
| **Issue labels for newcomers** | `good first issue` only if truly true |
| **Integration examples** | CLI recipes, hub setup, resolve/publish scripts |
| **Community project PR to Awesome list** | Social proof that the ecosystem isn’t one repo |

X role: occasional “new guide / new tag” pointers — not recruiter spam.

---

## Layer 4 — Operator growth (often underrated)

Networks die when **nobody runs infrastructure**.

| Idea | Notes |
|------|--------|
| **Hub / node operator docs** | Clear, boring, accurate |
| **Status & topology links** | If community monitors exist, list them (with provenance) |
| **Seeding guides** | Public-good framing: preserve content |
| **“Verify the network” checklist** | Resolve claim, fetch blob, optional hub query |
| **Operator corner on forum** | Searchable incidents and fixes |

X role: educational posts that respect operators’ time.

---

## Layer 5 — Creator & archival growth

Creators care about **audience and permanence**. Foundation voice should not pretend to be a startup growth team for a single app.

| Idea | Notes |
|------|--------|
| **Explain multi-app publishing** | Content on protocol ≠ locked to one UI |
| **Point to working publish paths** | Only what actually works today |
| **Archive / library framing** | “Published claims as a public library layer” |
| **Creator how-tos on forum** | Migrated from Discord lore |
| **No fake follower promises** | Trust > recruitment fantasies |

---

## Layer 6 — Governance & nonprofit trust growth

People fund and join what they **understand and trust**.

| Idea | Notes |
|------|--------|
| **Board page accuracy** | Roles public and current |
| **Quarterly transparency note** (forum) | What was maintained, broken, archived — dry facts |
| **Grants / fund process clarity** | Only if the process is real and responsive |
| **Donations language** | Official channels, utilitarian wording |
| **Decision logs** | Short forum posts when policy changes |

X role: rare links to transparency posts — not constant fundraising.

---

## Layer 7 — Narrative hygiene (AI & search era)

In 2025–2026, **official silence is summarized as death**.

| Practice | Effect |
|----------|--------|
| Fresh official pages with dates | Models and journalists have something to cite |
| Monthly educational X post | Breaks multi-month “no activity” patterns |
| Forum ship log | Chronology of reality |
| Clear deprecation banners | “Desktop deprecated; Nova replaces” reduces zombie docs |

This is not SEO spam. It is **public record maintenance**.

---

## Layer 8 — Relationship between Foundation and wider LBRY memory

Historical LBRY brand awareness still exists (legacy accounts, Odysee users, old press).

| Practice | Caution |
|----------|---------|
| Clarify Foundation vs legacy corporate surfaces | Don’t claim ownership of what isn’t Foundation |
| Answer “is LBRY dead?” with stack + Discord + forum | Don’t bash third parties |
| Separate **protocol health** from **any one company’s story** | Accurate and calmer |

---

## Anti-patterns (growth that damages the mission)

| Anti-pattern | Why it fails |
|--------------|--------------|
| Hype cycles with no artifact | Trains audience to ignore official posts |
| LBC market posting from Foundation account | Conflicts with nonprofit / trust posture |
| Forcing Discord culture onto X | Wrong medium; policy risk |
| Fake roadmaps | One missed date erases months of trust |
| Engagement farming | Attracts the wrong attention for a charity protocol |
| Announcing WIP as product | Sets CTO and board up to fail publicly |

---

## Suggested 90-day program (if the board wants a trial)

A minimal program that respects low capacity:

### Days 1–30 — Legibility

- [ ] Pin evergreen X post (site, Discord, forum, GitHub)  
- [ ] Publish or refresh a one-page “Where to go” on lbry.org  
- [ ] One X post: Discord is HQ  
- [ ] One X post: stack map / downloads  
- [ ] Move one repeated Discord how-to → forum guide  

### Days 31–60 — Heartbeat

- [ ] Two educational X posts (protocol glossary)  
- [ ] One community project spotlight (forum → X)  
- [ ] Ensure next software milestone has a **forum release ritual** before X  

### Days 61–90 — Proof

- [ ] Short forum transparency note (what exists, what is WIP, what is deprecated)  
- [ ] X link to that note  
- [ ] Review: did Discord onboarding get clearer? Did “is it dead?” replies get easier?  

Success is **clearer doors and fewer false death narratives** — not a follower spike.

---

## Roles & capacity (realistic)

| Capacity level | What is sustainable |
|----------------|---------------------|
| **Minimal** | 1 X post / month + link every real forum release |
| **Light** | Minimal + 1 forum guide / month exported from Discord |
| **Healthy** | Light + quarterly transparency note + occasional builder tags |

Do not design a strategy that requires a full-time social media hire if none exists. **Thin and true** scales; thick and fake collapses.

---

## How Discord strength becomes public strength

```text
Discord insight (repeated question / shipped patch / ops tip)
        │
        ▼
Forum or docs (searchable, citeable)
        │
        ▼
lbry.org link (if it belongs in the permanent map)
        │
        ▼
X / Reddit pointer (1 link, calm language)
        │
        ▼
New people enter Discord with context (not lost)
```

That loop is the growth engine. X is only one gear.

---

## Closing

LBRY does not need a louder circus.

It needs:

- a **living room** (Discord) that stays excellent,  
- a **library** (forum, site, GitHub) that remembers,  
- and a **street-facing window** (X) that tells the truth in public.

Make those three consistent, and “growth” becomes a side effect of **being findable, usable, and honest**.
