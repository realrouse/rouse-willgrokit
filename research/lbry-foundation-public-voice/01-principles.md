# Principles: a nonprofit public voice for LBRY

## Mission fit

The LBRY Foundation’s public bio and site describe a **non-profit** dedicated to the **growth, development, and adoption** of the LBRY network in a **bottom-up, community-driven** way.

Public communication should serve that mission by:

1. **Educating** people about the protocol and stack  
2. **Directing** builders, operators, and creators to working entry points  
3. **Documenting** real releases, governance, and infrastructure  
4. **Correcting** durable misconceptions (Inc vs Foundation vs protocol vs apps)  

It should not serve:

- Startup-style growth hacking  
- Market narratives around LBC  
- Personality clout  
- Speculative product theater  

## The “boring is OK” standard

A useful test for any draft post:

> If this post disappeared tomorrow, would anything **false** have been said, or anything **unverifiable** have been claimed?

| Pass | Fail |
|------|------|
| Links to a public page, repo, forum post, or tag | “Huge things coming” with no artifact |
| Explains a concept that remains true next year | Fake urgency / FOMO |
| Points people to Discord / forum for living discussion | Pretends X is the only place work happens |
| Admits quiet periods honestly | Invents monthly “updates” with no content |
| Uses LBC only as network utility language | Price, markets, “undervalued,” investment vibes |

**Boring, accurate, and findable beats exciting and empty.**

## Substance over substance-shaped noise

“Substance” here means **something a stranger can verify**:

- A forum announcement  
- A GitHub tag or README  
- A docs page  
- A board / governance page  
- A catalogued community project that already exists  
- A how-to someone can follow today  

“Hopes, wishes, and dreams” (even sincere ones) are not public product news. Work-in-progress can be discussed **in Discord** and **on the forum** with appropriate caution; X should wait for **durable artifacts**.

## 501(c)(3)-shaped boundaries (high level)

This is not legal advice. At a practical communications level, a U.S. charity-style posture usually means:

| Area | Guidance for public posts |
|------|---------------------------|
| **Education** | Core. Protocol explainers, how-tos, definitions. |
| **Mission programs** | Point to real Foundation activities, docs, grants process if active. |
| **Fundraising** | Allowed when real and proper; keep language dry; use official channels only. |
| **Commercial advertising** | Avoid sounding like a product ad agency; prefer “here is the open stack.” |
| **Political campaigns** | Do not intervene for/against candidates. |
| **Tokens** | Avoid investment promotion; utilitarian network use only. |

If something would look odd in an IRS-facing description of “educational activity about a free software content protocol,” it probably doesn’t belong on the official account.

## Voice: librarian, not hype man

Recommended tone for `@LBRYFoundation`:

- **Archivist / librarian** — “here is the durable record”  
- **Standards body** — “here is how the stack is organized”  
- **Community steward** — “here is where people actually talk and build”  

Avoid:

- Rocket-ship energy as a strategy  
- “Make LBRY great again” as an official slogan (fine for individuals; weak for a charity account)  
- Mocking other platforms  
- Over-claiming decentralization theater  

## Official vs community

| Who | Role |
|-----|------|
| **@LBRYFoundation** | Low volume, high trust, citeable |
| **Board members / CTO personally** | Can be more technical or informal; still careful with promises |
| **Community accounts** | Free to experiment, meme, debate (not speaking *as* the Foundation) |

Clarity matters: people should rarely wonder whether a tweet is Foundation policy or personal opinion.

## AI and drafting tools

Using AI to **draft, compress, or proofread** is optional and secondary.

Rules of thumb if used at all:

1. **Humans** supply facts and decide what is true.  
2. AI may rephrase only **already-approved substance**.  
3. AI must not invent releases, roadmaps, metrics, or quotes.  
4. Every post still needs a human “would I sign this as the Foundation?” check.

The problem to solve is **public legibility**, not content-factory volume.

## One-sentence doctrine

> **Post only facts that already exist; prefer dull truth over exciting emptiness; settle truth on forum and site; use X to point and teach; use Discord for the living conversation.**
